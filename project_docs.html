System Architecture & Specs

Functional Requirement Document (FRD)

Detailed product specifications, dynamic wireframes, workflows, and operations guide for the automated AI QA suite.

🎯 Product Purpose & Scope

The Antigravity QA Platform is a self-healing, multi-agent AI regression testing suite designed specifically for enterprise web apps, master data tables, and dynamic ERP platforms. By combining browser actions, system relationships, and auto-generated assertions, the platform delivers zero-configuration, self-correcting test suite creation.

📊 Core Functional Specifications
Feature Module Requirement Specification Auto-QA Strategy
Multi-Agent Test Case Generator Generates functional (happy paths, CRUD, selections) and boundary/negative/security scenarios based on target page structure and actions. Parallel execution of Agent 1 (Builder) and Agent 2 (Breaker) using asynchronous threading.
Coverage Auditor & Gap Loops Performs a rigorous 25-point audit matching every generated test suite against standard requirements (XSS, duplicates, missing cancels). Agent 3 (Auditor) loops back to Builder/Breaker with specific gaps if coverage is under 100%.
Relational Dependency Chaining Resolves relational database requirements by pre-executing and seeding prerequisite master records prior to loading dependent modules. Extracts dependency tags (e.g. `qualification_master, skill_master -> student_master`) and pre-seeds variables.
Inactive State Exclusions Verifies cascade deletion rules: records disabled or marked Status = Inactive in masters must not appear in dependent selection menus. Checks dropdown values count matching active state; asserts count of inactive item is 0.
Formula Fields & Calculated Inputs Tests calculation rules in real-time. Calculated / read-only fields must display correct formats and values, preventing negatives or zeros. Blocks TYPE commands on read-only fields; applies VERIFY_DISABLED and VERIFY_NON_ZERO checks instead.
🔒 Security & Error Detection Rules
  • XSS Injection Testing: Injects HTML elements <script>alert('XSS')</script> and checks if character sanitization occurs.
  • SQL Injection Testing: Appends sql payloads (e.g. ' OR 1=1 --) to input forms to verify backend safety.
  • Live Screen Inspector: Injects a post-execution DOM observer to discover inline validation labels (e.g., small.p-error, .invalid-feedback) and maps form field failures immediately.

🏷️ Locator Specifications & Smart Fallbacks

Because web forms dynamically modify component classes, the Playwright engine maps elements using strict hierarchies, falling back dynamically if standard identifiers are absent.

  • Cancel/Close Fallbacks: button:has-text("Cancel") $\rightarrow$ .p-dialog-footer button $\rightarrow$ .modal-header .btn-close.
  • Calculation Input Fallbacks: input#sort_ends_auto $\rightarrow$ input[name="sort_ends"] $\rightarrow$ input[readonly].

🔧 Operational Manual & Developer Setup

Follow these step-by-step developer guidelines to initiate, clean, and launch the server environment.

1. Run Backend Server

Avoid port conflicts (e.g., port 8000 already in use) by running the automated script launcher: 

.\run_server.bat

2. Execute Automated Regression Suites

Launch the dashboard by navigating to http://127.0.0.1:8000. Select your target module, choose your test filters, and click Run Suite.

3. Environment Variables Configuration (.env)

GEMINI_API_KEY=your_gemini_api_key_here
PORT=8000
HOST=127.0.0.1
💡 Playwright headed vs headless profiling

Modify test speed profiles dynamically in the dashboard UI:

  • Headed Mode (Visual Debug): Best for debugging. Slow-mo set to 300ms. Highlight elements enabled.
  • Headless Mode (Continuous Integration): Optimized for speed. Runs inside thread pool instantly. Step delay set to 200ms.
